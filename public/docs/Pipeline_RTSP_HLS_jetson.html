RTSP → DeepStream → HLS Pipeline

Reference commands for laptop test stream + Jetson DeepStream + mediamtx HLS conversion.

1. On Laptop — Create RTSP stream from video file

1Start mediamtx (RTSP server)

docker run -d --name mediamtx --restart unless-stopped -p 8554:8554 -p 8888:8888 -p 8889:8889 bluenviron/mediamtx

2Push the video as RTSP (keep terminal open)

ffmpeg -re -stream_loop -1 -i testing.mp4 \
  -c:v libx264 -preset ultrafast -tune zerolatency \
  -b:v 3M -maxrate 3M -bufsize 6M \
  -g 60 -pix_fmt yuv420p \
  -rtsp_transport tcp \
  -f rtsp rtsp://localhost:8554/cam1

RTSP feed is now available at rtsp://<laptop-ip>:8554/cam1

2. On Jetson — Verify the RTSP feed (optional)

Before running DeepStream, confirm the Jetson can pull the laptop's stream. Use TCP transport to avoid packet loss over Tailscale.

ffplay -rtsp_transport tcp -fflags nobuffer -flags low_delay \
  rtsp://100.121.142.58:8554/cam1

Replace IP: 100.121.142.58 is the laptop's Tailscale IP. Get yours with tailscale ip on the laptop.

3. On Jetson — Convert DeepStream RTSP to HLS

1Run DeepStream

Start your DeepStream pipeline. It will publish RTSP at rtsp://localhost:8554/ds-test

deepstream-app -c deepstream_config.txt

2Start mediamtx (HLS converter)

sudo docker rm -f mediamtx

sudo docker run -d --name mediamtx --restart unless-stopped \
  --network host \
  -e MTX_RTSP=no \
  -e MTX_HLSADDRESS=:8888 \
  -e MTX_HLSALWAYSREMUX=yes \
  -e MTX_WEBRTCADDRESS=:8889 \
  -e MTX_PATHS_DS-TEST_SOURCE=rtsp://localhost:8554/ds-test \
  -e MTX_PATHS_DS-TEST_SOURCEPROTOCOL=tcp \
  -e MTX_PATHS_DS-TEST_SOURCEONDEMAND=no \
  bluenviron/mediamtx

Environment variables

VariablePurpose
MTX_RTSP=noDisable mediamtx's own RTSP server (DeepStream owns 8554)
MTX_HLSADDRESS=:8888HLS endpoint port
MTX_HLSALWAYSREMUX=yesForce clean H.264 → HLS remuxing (more browser-compatible)
MTX_WEBRTCADDRESS=:8889WebRTC viewer endpoint (sub-second latency)
..._SOURCEWhere mediamtx pulls the RTSP from (DeepStream's output)
..._SOURCEPROTOCOL=tcpUse TCP transport, avoid UDP packet loss
..._SOURCEONDEMAND=noConnect to DeepStream immediately, not only when a viewer arrives

3Verify

# Check container is running
sudo docker ps | grep mediamtx

# Check it connected to DeepStream and is muxing HLS
sudo docker logs mediamtx | tail -20
# Look for: "is publishing to path 'ds-test'"
#          "is converting into HLS, 1 track (H264)"

# Verify HLS playlist is alive (need -L to follow cookie redirect)
curl -sL http://localhost:8888/ds-test/index.m3u8 | head -5
# Expect: #EXTM3U ... #EXT-X-VERSION:9 ...

4. View the dashboard stream in browser

Open on any device on the same VPN. Two URLs available:

HLS — for stream.html / hls.js dashboards · ~5–10s latency http://<jetson-ip>:8888/ds-test/index.m3u8 WebRTC — built-in mediamtx viewer · sub-second latency http://<jetson-ip>:8889/ds-test

5. Auto-start on boot

Docker daemon (mediamtx auto-starts via --restart unless-stopped)

# Check Docker daemon auto-starts
sudo systemctl is-enabled docker
# If output is "disabled", enable it:
sudo systemctl enable docker

# Test by rebooting
sudo reboot

# After login, confirm mediamtx is running
sudo docker ps | grep mediamtx

DeepStream auto-start (systemd service)

DeepStream isn't a container, so it needs its own service unit:

sudo tee /etc/systemd/system/deepstream.service > /dev/null <<'EOF'
[Unit]
Description=DeepStream YOLO Inference Pipeline
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=simple
User=nvidia
WorkingDirectory=/home/nvidia/deepstream
ExecStart=/usr/bin/deepstream-app -c /home/nvidia/deepstream/deepstream_config.txt
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable deepstream
sudo systemctl start deepstream

# Verify
sudo systemctl status deepstream
journalctl -u deepstream -f

Boot order: Docker starts → mediamtx auto-starts → systemd starts DeepStream. mediamtx will log connection refused for a few seconds before DeepStream is ready, then auto-connect on its 5-second retry. No manual intervention needed.

Manual control

# DeepStream
sudo systemctl restart deepstream
sudo systemctl stop deepstream
sudo systemctl status deepstream

# mediamtx
sudo docker restart mediamtx
sudo docker stop mediamtx
sudo docker logs -f mediamtx
