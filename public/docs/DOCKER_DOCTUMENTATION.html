Trinetra DeepStream 7.1 · Jetson

Docker command reference

After a PC restart, your container still exists — it's just stopped. Get back in with docker start -ai, not docker run. Running docker run again builds a brand-new container and loses everything you did inside the old one.
1

Set up (once)

$docker load -i trinetra-ds-7.1-arm64.tar

Load the DeepStream image into Docker from the .tar file. Run once, right after you copy the tar onto the device.

$docker run -it --runtime nvidia --net=host trinetra-ds:7.1 bash

Create and start a new container from the image — GPU access, host networking — and drop into a bash shell. Each run makes a fresh container, so use it only when you want a new one.

Tip: add --name trinetra here, then you can use the name instead of the container ID in every command below.

2

Each session

$sudo docker ps -a

List all containers — running and stopped — to find your container's ID or name.

$sudo docker start -ai <container id>

ResumeRestart an existing stopped container, attached and interactive — the same one with all your changes intact. This is how you get back in, including after a reboot.

$exit

Leave the container's shell. The container stops, since bash was its main process. Your data inside is kept.

3

Stop & remove

$sudo docker stop <container id>

Cleanly stop a running container from another shell. Everything inside stays intact — you can resume it later with start -ai.

$sudo docker rm <container id>

Delete a container permanently. Everything inside it is lost — only do this when you're truly done with it. The image stays, so you can always run a new one.

Replace <container id> with your ID from docker ps -a (or a name set with --name). If docker ps -a errors after a reboot, start the daemon with sudo systemctl start docker.
