YOLO26 · DeepStream · Jetson

Trinetra DeepStream 7.1 — deployment guide

Get the trinetra-ds:7.1 container onto a Jetson, then run YOLO26 inference through DeepStream with an RTSP output stream.

Reopening the container later: after a reboot it still exists — it's just stopped. Get back in with docker start -ai, not docker run. A second docker run builds a brand-new container and loses everything you set up inside the old one.
1

Transfer the image to the Jetson

laptop → Jetson
Download .tar from Google Drive

Saves trinetra-ds-7.1-arm64.tar to your machine. If Drive shows a virus-scan notice for the large file, click Download anyway.

$scp trinetra-ds-7.1-arm64.tar <user>@<jetson-ip>:~/

Copy the tar to the Jetson over SSH. Run this from the folder where you downloaded it. Replace <user> and <jetson-ip> with the Jetson's login and address.

2

Prepare the Jetson

Jetson host · outside container
$sudo nvpmodel -p --verbose $sudo nvpmodel -m 2 $sudo nvpmodel -q $sudo jetson_clocks

Set the Jetson to power mode 2, confirm it (-q), then lock the clocks to max with jetson_clocks for full inference performance. Run on the host, not inside the container.

$docker load -i trinetra-ds-7.1-arm64.tar

Load the DeepStream image into Docker from the tar you copied over. One time per Jetson.

3

Start the container

Jetson host
$docker run -it --runtime nvidia --net=host trinetra-ds:7.1 bash

First timeCreate the container and drop into its shell — GPU access and host networking enabled. Do the model setup in Phases 4–7 from inside this shell.

Tip: add --name trinetra here so you can use the name instead of the container ID everywhere below.

$sudo docker ps -a

List all containers, running and stopped, to find your container's ID or name.

$sudo docker start -ai <container id>

ResumeRestart your existing container, attached and interactive — same container, all your work intact. Use this for every session after the first, including after a reboot.

$exit

Leave the container's shell. It stops (bash was its main process); your data is kept. Stop a running one from another shell with sudo docker stop <container id>, or delete it for good with sudo docker rm <container id>.

4

Export the YOLO26 model

inside container
$cd ultralytics $wget https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26s.pt $python3 export_yolo26.py -w yolo26s.pt --simplify --batch 1

Pull the YOLO26-small weights and export to a simplified ONNX with batch size 1, producing yolo26s.onnx.

5

Build the DeepStream-Yolo plugin

inside container
$cp yolo26s.onnx labels.txt ~/DeepStream-Yolo $cd ~/DeepStream-Yolo $export CUDA_VER=12.6 $make -C nvdsinfer_custom_impl_Yolo clean && make -C nvdsinfer_custom_impl_Yolo

Move the ONNX and labels into the DeepStream-Yolo repo, set the CUDA version, then clean and compile the custom bbox-parser plugin (.so).

6

Write the config files

inside container
$nano config_infer_primary_yolo26.txt

Inference config — model path, precision, classes, and the custom parser. Open it, then paste the contents below.

config_infer_primary_yolo26.txt 
[property]
# GPU device ID. On Jetson always 0 (single GPU)
gpu-id=0

# Pixel normalization: output_pixel = input_pixel * net-scale-factor
# 0.0039215697... = 1/255  → maps 0-255 to 0-1 (standard for YOLO)
# 1.0 = no normalization
net-scale-factor=0.0039215697906911373

# Input color format the model expects
# 0=RGB  1=BGR  2=GRAY  3=RGBA  4=BGRx
model-color-format=0

# Path to ONNX model (resolved relative to this config file)
onnx-file=yolo26s.onnx

# Path to TensorRT engine. Built from ONNX on first run if missing.
# Convention: model_b<batch>_gpu<id>_<precision>.engine
model-engine-file=model_b1_gpu0_fp16.engine

# INT8 calibration table - only used when network-mode=1 (INT8)
#int8-calib-file=calib.table

# Class labels file (one label per line, indexed 0..N-1)
labelfile-path=labels.txt

# Inference batch size. Must match engine file's batch dim
batch-size=1

# Inference precision
# 0=FP32  1=INT8  2=FP16  3=BEST (auto-select)
network-mode=2

# Number of detection classes the model outputs (COCO=80)
num-detected-classes=80

# Frame skipping
# 0=infer every frame  N=skip N frames between inferences (reuse last result)
interval=0

# Unique ID for this GIE - must match [primary-gie] gie-unique-id in app config
gie-unique-id=1

# Where this GIE runs in the pipeline
# 1=Primary (full frame)  2=Secondary (on detected objects from upstream GIE)
process-mode=1

# Network output type
# 0=Detector  1=Classifier  2=Segmentation  3=Instance-Seg  100=Other (custom)
network-type=0

# Bounding-box clustering applied to raw detections
# 0=GroupRectangles  1=DBSCAN  2=NMS  3=DBSCAN+NMS hybrid  4=None
cluster-mode=2

# Network input dimensions: channels;height;width (overrides ONNX dims)
infer-dims=3;640;640

# Letterbox resizing - preserve aspect ratio with padding
# 1=maintain aspect (pad)  0=stretch to fit
maintain-aspect-ratio=1

# Padding placement when maintain-aspect-ratio=1
# 1=symmetric (center)  0=asymmetric (right/bottom only)
symmetric-padding=1

# TensorRT workspace size (MB) - larger allows better kernel tactic selection
#workspace-size=2000

# Custom bbox parser symbol exported from custom-lib-path .so
parse-bbox-func-name=NvDsInferParseYoloCuda

# Compiled custom inference plugin (built in section 05)
custom-lib-path=nvdsinfer_custom_impl_Yolo/libnvdsinfer_custom_impl_Yolo.so

# Custom engine builder for ONNX models with non-standard ops
engine-create-func-name=NvDsInferYoloCudaEngineGet

[class-attrs-all]
# Confidence threshold - detections below this are dropped before clustering
# Range: 0.0 to 1.0  (lower=more detections, higher=stricter)
pre-cluster-threshold=0.25

# Max detections kept after NMS/clustering (per frame)
topk=300

7

Run DeepStream

inside container
$deepstream-app -c deepstream_app_config.txt

Launch the pipeline. The first run builds the TensorRT engine from the ONNX (slow once, cached after). With this config the output is served over RTSP.

View the stream at rtsp://<jetson-ip>:8554/ds-test (port and path come from the [sink1] section above).

8

Move a file from your laptop into the container

laptop → container · any time
$scp <file> <user>@<jetson-ip>:~/

Step 1Send the file from your laptop to the Jetson's home folder over SSH. Run it from wherever the file lives on your laptop.

$docker cp ~/<file> <container id>:/root/

Step 2On the Jetson, copy it from the host into the container. docker cp is the container version of cp — plain cp can't reach a container's filesystem unless you started it with a mounted volume (-v).

To pull a file back out of the container, reverse it: docker cp <container id>:/root/<file> ~/

Replace <container id> with your ID from docker ps -a, or a name set with --name.

If docker can't connect after a reboot, start the daemon: sudo systemctl start docker.
