Jetson Auto-Start Runbook

Jetson DeepStream + mediamtx + Dashboard

Single document covering full teardown and rebuild of the auto-start pipeline.

Components installed by this runbook:

  • mediamtx — Docker container, HLS/RTSP gateway (HLS on 8888, WebRTC on 8889)
  • mediamtx-postsync — systemd service, restarts mediamtx after NTP sync (handles Jetson RTC drift)
  • trinetra-dashboard — systemd service, FastAPI dashboard on port 8080
  • deepstream-yolo — user systemd service, runs deepstream-app with HDMI display + RTSP at rtsp://localhost:8554/ds-test
  • GDM3 auto-login — so the user session (and DeepStream window) starts without manual login
Boot sequence:
NTP sync → mediamtx restart → GDM auto-login → graphical user session → DeepStream pipeline → mediamtx pulls RTSP → HLS available
Note on mediamtx: No separate installation needed. The docker run bluenviron/mediamtx command in Step 3 auto-pulls the image on first run.

00Install Docker (skip if already installed)

docker --version || sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker nvidia   # so 'nvidia' can run docker without sudo (logout/login after)

Verify:

docker --version
sudo systemctl is-active docker

JetPack 6 usually has Docker pre-installed — the first line is a no-op in that case.

01Cleanup (run this to remove any prior setup)

Stops and removes every service/file this runbook creates. Safe to run even if some don't exist.

# Stop and remove user-level deepstream service
systemctl --user disable --now deepstream-yolo.service 2>/dev/null
rm -f ~/.config/systemd/user/deepstream-yolo.service
systemctl --user daemon-reload

# Stop and remove system-level services
sudo systemctl disable --now deepstream-yolo.service 2>/dev/null
sudo systemctl disable --now trinetra-dashboard.service 2>/dev/null
sudo systemctl disable --now mediamtx-postsync.service 2>/dev/null
sudo rm -f /etc/systemd/system/deepstream-yolo.service
sudo rm -f /etc/systemd/system/trinetra-dashboard.service
sudo rm -f /etc/systemd/system/mediamtx-postsync.service
sudo systemctl daemon-reload

# Remove mediamtx container
sudo docker rm -f mediamtx 2>/dev/null

# Verify all gone
ls /etc/systemd/system/deepstream-yolo.service /etc/systemd/system/trinetra-dashboard.service /etc/systemd/system/mediamtx-postsync.service ~/.config/systemd/user/deepstream-yolo.service 2>&1
sudo docker ps -a | grep mediamtx

The ls should show "No such file or directory" for each, and docker ps should show no mediamtx row.

03mediamtx Docker container

sudo docker rm -f mediamtx 2>/dev/null

sudo docker run -d --name mediamtx --restart unless-stopped \
  --network host \
  -e MTX_RTSP=no \
  -e MTX_HLSADDRESS=:8888 \
  -e MTX_HLSALWAYSREMUX=yes \
  -e MTX_WEBRTCADDRESS=:8889 \
  -e MTX_PATHS_DS-TEST_SOURCE=rtsp://localhost:8554/ds-test \
  -e MTX_PATHS_DS-TEST_RTSPTRANSPORT=tcp \
  bluenviron/mediamtx

--restart unless-stopped makes Docker auto-start it on every boot.

04mediamtx-postsync systemd service

Restarts the mediamtx container once NTP has corrected the clock. Without this, mediamtx starts with a wrong system time at boot (Jetson dev kit has no RTC battery) and the HLS muxer takes ~3 minutes to recover.

sudo tee /etc/systemd/system/mediamtx-postsync.service > /dev/null <<'EOF'
[Unit]
Description=Restart mediamtx after NTP sync
After=systemd-time-wait-sync.service docker.service
Wants=systemd-time-wait-sync.service
Requires=docker.service

[Service]
Type=oneshot
ExecStart=/usr/bin/docker restart mediamtx
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable systemd-time-wait-sync.service
sudo systemctl daemon-reload
sudo systemctl enable mediamtx-postsync.service

05GDM3 auto-login + force X11

DeepStream's EGL sink needs X11 (not Wayland), and the user service needs an actual logged-in session.

sudo tee /etc/gdm3/custom.conf > /dev/null <<'EOF'
# GDM configuration storage
[daemon]
WaylandEnable=false
AutomaticLoginEnable=true
AutomaticLogin=nvidia

[security]

[xdmcp]

[chooser]

[debug]
EOF

06Trinetra dashboard systemd service

System-level service for the FastAPI dashboard.

# Make sure deps are installed once
sudo apt install -y python3-fastapi python3-uvicorn 2>/dev/null

sudo tee /etc/systemd/system/trinetra-dashboard.service > /dev/null <<'EOF'
[Unit]
Description=Trinetra Watch Dashboard (FastAPI)
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=simple
User=nvidia
WorkingDirectory=/home/nvidia/trinetra-watch-main
Environment=HOME=/home/nvidia
ExecStart=/usr/bin/python3 -m uvicorn main:app --host 0.0.0.0 --port 8080
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now trinetra-dashboard.service

07DeepStream user service (HDMI display)

User-level service, runs inside the auto-logged-in graphical session so it inherits DISPLAY and XAUTHORITY automatically.

mkdir -p ~/.config/systemd/user

cat > ~/.config/systemd/user/deepstream-yolo.service <<'EOF'
[Unit]
Description=DeepStream YOLO Pipeline (user session)
After=graphical-session.target
PartOf=graphical-session.target

[Service]
Type=simple
WorkingDirectory=/home/nvidia/DeepStream-Yolo
ExecStartPre=/bin/sleep 10
ExecStart=/usr/bin/deepstream-app -c deepstream_app_config.txt
Restart=always
RestartSec=10

[Install]
WantedBy=graphical-session.target
EOF

systemctl --user daemon-reload
systemctl --user enable deepstream-yolo.service

Restart=always ensures the window comes back if you accidentally close it.

08Reboot

sudo reboot

After boot you should see (in order):

  1. No password screen — GDM auto-logs in nvidia
  2. Desktop appears on HDMI
  3. ~10 seconds later: DeepStream tiled-display window opens
  4. mediamtx pulls the RTSP feed shortly after
  5. Dashboard reachable at http://<jetson-ip>:8080
  6. HLS reachable at http://<jetson-ip>:8888/ds-test/

# Did the post-sync service run cleanly?
systemctl status mediamtx-postsync.service

systemctl status trinetra-dashboard.service

# Confirm only ONE deepstream-app process is running
ps aux | grep deepstream-app | grep -v grep

Common operations

# Restart deepstream window (after closing it manually)
systemctl --user restart deepstream-yolo.service

# Stop deepstream just for now
systemctl --user stop deepstream-yolo.service

# Disable deepstream from auto-starting on boot
systemctl --user disable deepstream-yolo.service

# Re-enable
systemctl --user enable --now deepstream-yolo.service

# Same pattern for system services (use sudo, no --user flag)
sudo systemctl restart trinetra-dashboard.service
sudo systemctl restart mediamtx-postsync.service
sudo docker restart mediamtx

# Tail live logs
journalctl --user -u deepstream-yolo.service -f
sudo journalctl -u trinetra-dashboard.service -f
sudo docker logs -f mediamtx

Notes / gotchas seen during setup

  • Trailing whitespace in DeepStream config URIs caused Failed to load uri file: No such file or directory. The sed cleanup in Step 2 prevents this.
  • CRLF line endings from copy-paste also break the parser; same sed handles it.
  • enc-type=0 (HW encoder) fails on Orin Nano — use enc-type=1 (software). On Orin NX/AGX you can use 0.
  • System-level deepstream service vs user-level — only one should exist. The user-level version is the right one when you want the HDMI window. Step 1 cleanup removes both to avoid two windows.
  • GDM3 config must have AutomaticLoginEnable=true and AutomaticLogin=nvidia uncommented and not mistakenly include the descriptive comment line without a #.
